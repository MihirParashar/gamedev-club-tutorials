# Game Dev Club Tutorial Site: v1 Spec

Status: **approved 2026-11-11, revised 2026-11-12.** The first version (three tutorials, all about Rain Dodge) is saved as the git tag `v1`. The revision widens the course: Rain Dodge is one lesson of several, and the course ends with the member able to make their own game. See README.md for how the site works.

## Audience

IMSA game dev club members. Assume the Python taught in the mandatory intro CS class and nothing beyond it. Some members code in their free time, but no tutorial may depend on that.

Machines: roughly 70% Windows, 30% Mac. Some members use school loaner laptops (Windows, not locked down, slow).

Main blocker today: setup, not concepts. At the first session several people could not install pygame (wheel errors), and the rest waited while leads debugged.

*Unverified:* Mihir was not at that session. He will ask whoever ran it (1) where people got stuck and (2) what finishers did next. Update this section when he hears back.

## Tools

Python and pygame only. Unity and Godot help stays in-person mentoring. Git is not required of members.

Decided during build (2026-11-11): install `pygame-ce`, not `pygame`. python.org now offers Python 3.15, and `pygame` 2.6.1 has ready-made builds only up to 3.13, which is the likely cause of the failed installs at the first meeting (not yet confirmed on a member laptop). `pygame-ce` 2.5.8 has builds for 3.10 through 3.15 on Windows and Mac, so no Python version needs pinning.

## Lessons (one ordered list)

Each game lesson is a small complete game built from an empty file. It reuses what earlier lessons taught and adds a few new skills. The skills were chosen by asking what a member needs in order to build a game of their own design.

| # | Lesson | New skills | Source |
|---|---|---|---|
| 1 | Set up Python and pygame | A working install, running a file | New |
| 2 | Rain Dodge | The game loop, keyboard control, rectangles, collisions, text | The club's slide deck, converted |
| 3 | Extend Rain Dodge | Lives, restarting, saving to a file | The deck's challenge slide, with worked solutions |
| 4 | Pop | Mouse clicks, circles, a countdown, sound | New |
| 5 | Brick Buster | Speed in two directions, bouncing, grids from loops, winning | New |
| 6 | Coin Climb | Gravity and jumping, levels written as text, solid walls | New |
| 7 | Shoot Back | Classes, bullets with a cooldown, enemies with health | New |
| 8 | Start your own game | Screens, pausing, planning a game small enough to finish | New. Starter template plus a planning guide |

Rain Dodge keeps its credit to Tech With Tim's tutorial. The other games are the club's own and use no outside assets: shapes drawn in code, and sounds generated by scripts in the repo.

Suggested use at meetings (Mihir to confirm): lessons 1 to 3 before Thanksgiving, one of lessons 4 to 7 taught at the first December meeting with the rest as self-study, and lesson 8 run as a mini jam at the second.

## Tutorial page template

Goal (what you will have at the end), estimated time, prerequisites, steps, common errors and fixes, finished code, next tutorial. After each step: a checkpoint that says "run it, you should see…" plus the errors likely at that step. This is the format the Rain Dodge deck already uses. Screenshots come from Mihir's test runs.
